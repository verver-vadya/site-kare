# Каре — сайт салона стрижки и окрашивания

Тестовый проект: сайт вымышленного салона «Каре» (Москва, Малая Бронная) в стиле модного журнала. Одна страница: обложка, прайс, мастера, работы, запись, адрес; плюс политика конфиденциальности и страница 404.

- Превью: https://verver-vadya.github.io/site-kare/ (после включения GitHub Pages)
- Стек: чистый HTML, CSS и немного JS, без сборки; сделан из [site-template](https://github.com/verver-vadya/site-template).
- Шрифты: Fira Sans, Fira Sans Extra Condensed, Playfair Display (OFL), лежат в `assets/fonts/`.

## Как устроена обложка

Название салона стоит «за» головой модели, как на обложке журнала. Это три слоя одного кадра:

1. фото (`assets/img/hero-l-*.webp` для широких экранов, `hero-p-*.webp` для вертикальных);
2. буквы «КАРЕ» в `<svg>`: `viewBox` равен размеру фото, а `preserveAspectRatio` повторяет `object-fit: cover` у картинки, поэтому буквы всегда стоят на тех же местах кадра;
3. вырезанная из того же фото голова (`hero-*-cut-*.webp`, прозрачный фон) поверх букв.

Над головой на исходном фото не было места, фон и макушка достроены. Если меняете фото, все три слоя нужно делать заново из одного кадра одного размера.

Обложка перестраивается по форме окна: на телефоне и планшете стоя вертикальный кадр и анонсы под ним, на низких и почти квадратных окнах широкий кадр и анонсы в ряд, на широком экране компьютера кадр на всю высоту и анонсы колонкой справа.

## Что поменять под настоящий салон

Все тексты, цены, мастера и адрес — примеры. Где что лежит:

| Что | Где |
| --- | --- |
| Название, адрес, телефон, часы | `index.html`: шапка, обложка, разделы «Запись» и «Адрес», подвал; `privacy.html` |
| Услуги и цены | `index.html`, раздел `id="services"`; список услуг в форме записи (`<select id="b-service">`) должен совпадать |
| Мастера | `index.html`, раздел `id="masters"` и список `<select id="b-master">` |
| Фото | `assets/img/`, источники в `CREDITS.md` |
| Цвета, шрифты, отступы | переменные в начале `assets/css/style.css` |
| Адрес сайта | `example.ru` в `index.html`, `privacy.html`, `sitemap.xml`, `robots.txt` |
| Политика конфиденциальности | `privacy.html`, всё в `[ЗАПОЛНИТЬ: …]` |

Клик по услуге в прайсе или по «Записаться к …» у мастера сам выбирает её в форме записи (`assets/js/main.js`).

## Запись

Сейчас на сайте своя форма: заявка уходит администратору через [Formspree](https://formspree.io) (вписать адрес формы в `action` вместо `YOUR_FORM_ID`; пока его нет, форма честно пишет, что не подключена). Администратор перезванивает и подтверждает время.

Для настоящего салона лучше подключить сервис онлайн-записи (DIKIDI или YClients): там живое расписание мастеров, напоминания клиентам и журнал для администратора. Аккаунт регистрирует салон, на сайт вставляется их виджет на место формы (место отмечено комментарием в `index.html`).

## Запуск локально

Сборки нет, нужен любой статический сервер:

```bash
python3 -m http.server 8000
# или
npx serve .
```

Открыть http://localhost:8000.

## Автопроверка

Ловит типичные ошибки: ссылки на `#` и битые ссылки, кнопки без реакции на наведение и нажатие, форму, которая молчит при ошибке или отправляется дважды, меню, которое не закрывается, ошибки в консоли, мелкие зоны нажатия, сломанную 404, заглушки и штампы в текстах. А ещё:

- **размеры экрана** от 320 до 2560 px, ноутбук 1280×630 и масштаб Windows 125 % и 150 %: горизонтальная прокрутка и **наложения** (картинка на тексте, в том числе при наведении; текст на тексте). Задуманное наложение помечается атрибутом `data-overlap-ok`;
- **окна** (`<dialog>`): покадрово следит за выездом (без отката назад, рывка за один кадр и подскока в конце), фокус не на «Закрыть», закрытие по Esc и кликом мимо, поведение без анимаций;
- **движение**: анимации `width`, `letter-spacing` и других свойств, которые пересчитывают страницу, `transition: all`, правило «убрать всё движение» для режима без анимаций;
- **ссылки шире своей надписи** (тап по пустому месту уводит не туда);
- **размеры блоков по сравнению с прошлой версией** (в pull request сравнивает с `main`): картинки, заголовки, секции, которые изменились. Это не ошибка, а список, чтобы сверить, что так и задумано.

Скриншоты: вся страница на 375 / 768 / 1280 и первый экран на 1280×630, 1920×1080 и при масштабе 125 %.

- **В pull request** запускается сама (Actions → «Проверка сайта»). Отчёт в Summary, скриншоты в артефакте `screenshots`.
- **Локально** (нужен Node.js 20+):

  ```bash
  cd .github/check
  npm ci
  npx playwright install chromium   # один раз
  npm run check                     # черновик: заглушки только предупреждают
  npm run check:release             # перед публикацией: заглушки тоже ошибки
  npm run check -- --base /путь/к/прошлой/версии   # плюс сравнение размеров блоков
  ```

  Прошлую версию удобно достать так: `git worktree add /tmp/site-main main`.

  Отчёт и скриншоты появятся в папке `.check/`.

Чего проверка не видит (дизайн, смысл текстов, «шаблонность»), смотрим руками по `.github/CHECKLIST.md`.

## Публикация

- **Превью**: автоматически на GitHub Pages после пуша в `main` (`https://<логин>.github.io/<репозиторий>/`).
- **Боевой сайт**: загрузить файлы на российский хостинг (Timeweb, Beget, Reg.ru) по FTP/SFTP или в Yandex Object Storage, без папок `.github`, `.claude`, `.check` и `node_modules`. Настроить на хостинге `404.html` как страницу ошибки 404. Перед этим пройти `npm run check:release`. Только после явного согласия владельца.
